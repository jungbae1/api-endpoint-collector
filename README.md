# API Endpoint Collector (Chrome 확장, Manifest V3)

웹 애플리케이션의 **보안 진단 / 디버깅**을 돕기 위한 로컬 도구입니다.
현재 열려 있는 탭에서 발생하는 **네트워크 API 요청**과, 페이지에 로드된
**JS 번들 안에 숨어 있는 API 경로**를 수집해 한눈에 정리해 줍니다.

> 모든 처리는 브라우저 안에서만 일어나며, 수집한 데이터는 외부로 전송되지
> 않습니다. 결과는 `chrome.storage.session`(브라우저 세션 동안만 유지)에만
> 임시 저장됩니다.

---

## 파일 구조

| 파일 | 역할 |
|------|------|
| `manifest.json` | 확장 메타데이터 · 권한 선언 (MV3) |
| `background.js` | 서비스 워커. `chrome.webRequest`로 fetch/XHR 요청을 **관찰만** 하여 URL·메서드·상태코드 수집 |
| `content.js` | 콘텐츠 스크립트. 로드된 `.js` 파일과 인라인 스크립트를 받아 정규식으로 API 경로 **정적 추출** |
| `popup.html` | 팝업 UI 마크업 + 인라인 스타일 |
| `popup.js` | 테이블 렌더링, 검색/필터, 복사, JSON 내보내기, 초기화 |

---

## 설치 방법 (압축 해제된 확장 로드)

1. Chrome 주소창에 `chrome://extensions` 입력 후 이동
2. 오른쪽 위 **개발자 모드(Developer mode)** 토글 켜기
3. **압축 해제된 확장 프로그램을 로드합니다(Load unpacked)** 클릭
4. 이 폴더(`manifest.json`이 있는 폴더)를 선택
5. 툴바에 아이콘이 생기면 설치 완료 (아이콘이 안 보이면 퍼즐 조각 메뉴에서 고정)

---

## 사용 / 테스트 방법

1. 진단하려는 웹 페이지를 탭에서 엽니다.
2. 페이지와 상호작용(로그인, 버튼 클릭, 스크롤 등)하여 API 요청이 발생하게 합니다.
3. 확장 아이콘을 클릭해 팝업을 엽니다.
   - 팝업이 열릴 때 자동으로 JS 정적 분석을 실행하고, 네트워크 수집 결과와 합쳐 표시합니다.
4. 표 열 구성: **[메서드 | 경로 | 출처(network/js) | 상태코드]**
   - `/api/`, `/v1/`, `/v2/`, `/graphql` 등 **API로 보이는 경로**는 초록색으로 하이라이트됩니다.
   - `출처=network` : 실제로 호출이 관찰된 요청
   - `출처=js` : 코드에는 있으나 아직 호출되지 않은 **숨은 엔드포인트 후보**
5. 상단 기능:
   - **검색** : 경로/메서드로 즉시 필터
   - **API만** : API 패턴에 맞는 행만 표시
   - **새로고침** : 정적 분석 재실행 + 최신 네트워크 결과 반영
   - **복사** : 현재 필터된 결과를 JSON으로 클립보드에 복사
   - **JSON 내보내기** : `.json` 파일로 다운로드
   - **초기화** : 현재 탭의 수집 결과 삭제

### 동작 확인 팁
- 상태코드가 `-` 면 아직 응답이 안 왔거나 JS에서만 발견된 경로입니다.
- 상태코드 `ERR`(=0)은 차단/네트워크 실패를 의미합니다.
- 페이지를 **새 URL로 이동**하면 해당 탭의 수집 결과는 자동 초기화됩니다.
- `chrome://`, 확장 페이지 등 특수 페이지에서는 정적 분석 주입이 제한됩니다.

## 요청한 권한과 이유 (최소 권한 원칙)

| 권한 | 용도 |
|------|------|
| `webRequest` | fetch/XHR 요청의 URL·메서드·상태코드 **관찰** (차단용 `webRequestBlocking`은 사용 안 함) |
| `tabs` | 탭별로 결과를 분리 저장하고, 탭 이동/종료 시 정리 |
| `activeTab` | 팝업을 연 현재 탭 접근 |
| `scripting` | 활성 탭에 정적 분석 스크립트(`content.js`)를 필요할 때만 주입 |
| `storage` | 수집 결과를 `storage.session`에 임시 보관 |
| `host_permissions: <all_urls>` | 임의 사이트의 요청을 관찰하고 교차 출처 JS를 받아 분석하기 위함 |

## 정규식 패턴과 오탐(false positive) 저감 설명

정적 분석은 "실제 호출"이 아니라 **코드 문자열 매칭**이므로 본질적으로
오탐이 생길 수 있습니다. 아래와 같이 패턴과 후처리를 설계했습니다.
(구현: `content.js`)

### 패턴 A — 절대 URL 형태
```
https?:\/\/[^\s"'`<>]+?\/(?:api|v\d+|graphql)\/[A-Za-z0-9_\-./:{}]*
```
- `https?` : http/https 모두 허용
- `[^\s"'`<>]+?` : 호스트+경로 앞부분. 공백·따옴표·백틱·꺾쇠를 제외해
  **문자열 경계를 넘어 과하게 매칭되는 것을 방지**(게으른 `+?` 사용)
- `\/(?:api|v\d+|graphql)\/` : `/api/`, `/v1/`, `/v2/`, `/graphql/` 처럼
  **API로 보이는 세그먼트를 반드시 포함**하도록 강제 → 오탐 억제의 핵심

### 패턴 B — 상대 경로 형태
```
(?<![A-Za-z0-9_])\/(?:api|v\d+|graphql)(?:\/[A-Za-z0-9_\-.:{}]+)*
```
- `(?<![A-Za-z0-9_])` : 앞에 영숫자/언더스코어가 오면 제외.
  예) `/scapi/`의 `api`처럼 **다른 단어의 일부**를 잡지 않도록 함
- 세그먼트 문자셋을 제한해 **JS 코드 조각을 통째로 삼키는 것**을 방지

### 공통 후처리 (추가 오탐 저감)
- 결과 끝에 붙는 구두점(`" ' ` ) , ;`) 제거
- 길이가 너무 짧은 매칭 제외
- `.js/.css/.png/.woff` 등 **정적 리소스 확장자로 끝나는 경로 제외**
- 파일당 과도한 매칭 시 조기 중단(폭주 방지)

### 남는 한계
- 템플릿 리터럴/문자열 결합으로 **런타임에 조립되는 경로**(예:
  `` `/api/${resource}/${id}` ``)는 조각으로만 잡히거나 놓칠 수 있습니다.
- 그래서 `출처=js` 결과는 **"후보"**로 보고, 실제 존재 여부는
  `출처=network` 결과 및 직접 호출 테스트로 **교차 확인**하길 권장합니다.

## 주의 / 범위
